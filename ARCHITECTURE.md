## Application boundary

`main.go` creates `internal.App` and passes it to `ui.Run(app, title)`. `internal/app.go` is the framework-independent business entry point for serial connections, sending, capture/export, counters and operation status. Its settings actions and persistence helpers own baud rates, presets, dirty revisions and shutdown flushing. This layer does not import MyGo.

`ui/` owns controls, interaction drafts, confirmations, native file dialogs and the receive-display model. It calls App commands and implements `internal.View`: `Dispatch(func())` posts results through `Window.Update`, and `AppendEvents([]internal.Event)` updates the display. App commands and observable state belong to the frontend thread; serial enumeration/open/close, transmission, file I/O and settings writes run in background workers. A replacement UI supplies this adapter without reimplementing those operations. Control-line confirmation preserves its synchronous driver-error result.

## Modules

| Location | Responsibility |
| --- | --- |
| `main.go` | Application name, version, window title, and startup wiring |
| `internal/app.go` | Connections, sending, capture/export, counters, and operation status |
| `internal/settings_actions.go`, `internal/settings_save.go` | Settings rules, dirty revisions, snapshots, persistence, and exit flushing |
| `internal/session.go`, `internal/format.go` | Serial sessions, receive events, and text/HEX encoding and decoding |
| `ui/` | Native MyGo controls, interaction drafts, confirmations, dialogs, and receive-display state |
| `communication/serialport/` | Device enumeration, serial configuration, driver control, and I/O |
| `config/` | Settings schema, normalization, executable-local paths, and persistence format |
| `assets/`, `cmd/appicon/` | Embedded defaults and icons, and build-time icon generation |

Business code must not import MyGo or another UI framework. Dependencies are pinned in `go.mod`; the native UI uses [MyGo](https://github.com/egoist/mygo), without WebView, Node.js, or TypeScript bindings.

## Settings and persistence

- Resolve executable symlinks and use only the `config.toml` beside the actual executable. Never search the working directory or a user configuration directory, and never fall back to another directory after a save failure.
- The repository-root [`config.toml`](config.toml) is the sole default template. Just copies it to the generated `assets/default-config.toml` before compilation; Go decodes that embedded resource. The executable is standalone and does not read the repository template at runtime.
- Create defaults immediately if the executable-local file is missing. Loading must not overwrite an existing file, including one that cannot be read or decoded. Initialize omitted scalar fields from the embedded defaults; an omitted or explicitly empty preset list stays empty.
- Committed edits mark `settingsDirty`, without per-keystroke writes or save timers. Property-dialog drafts stay separate until confirmation.
- Save dirty settings on actual use: successful port open, accepted send, successful log export or capture start, confirmed port-property change, preset addition or confirmed deletion, and immediately applied display, language, or preset-panel changes. Skip unchanged uses and exits, and do not save per packet during timed or looping sends.
- The persisted `ParseSendEscapes` preference defaults to false. Main and preset sends share the same encoder; it expands `\\`, `\a`, `\b`, `\f`, `\n`, `\r`, `\t`, `\v`, `\0`, and `\xNN` only in text mode. Literal text uses the selected encoding, `\xNN` emits a raw byte, and invalid escapes fail before transmission. CRLF is appended after expansion.
- Serialize background writes using immutable snapshots with independently copied preset and baud-rate slices. Clear dirty state only for a successfully saved current revision; an older save cannot clear a newer edit.
- Preserve dirty state and save errors after failure so the next use can retry. Later operation-success notifications must not hide a save error. Normal shutdown drains work and flushes remaining drafts through `App.Shutdown`.
- The main and plot windows use separate MyGo `WindowOptions.StateKey` values and a shared `WindowStateStore` backed by `[Window]` and `[CurveWindow]` in `config.toml`, not MyGo's user-data JSON file. MyGo debounces move/resize/state events, keeps normal bounds across maximize and minimize, and stores Windows native-pixel bounds for mixed-DPI restoration. It validates visibility against each display's `WorkArea` (at least 100x50 DIPs); otherwise it centers the window at the saved size. Older configurations without native pixel bounds are centered when connected displays use different scale factors. Closing the plot queues a background settings save if its state changed. The main window closes the plot explicitly before the native owner destroys it, and `App.Shutdown` flushes the final state.
- Configure MyGo's locale as session-only. The executable-local `config.toml` remains the sole preferences store; language switching does not translate or reset user data.
- Generic persistence round-trips retained curve values, including invalid legacy values. Curve commands validate introduced edits and the selected acquisition schema instead of rejecting unrelated unchanged legacy entries; full-value matching consumes retained entries independently of list indices. Old over-limit lists may shrink incrementally but cannot grow. Invalid active selections remain editable with an explicit error and acquisition stopped. Compiled active-schema snapshots preserve metadata-only edits without recompiling regexes.

## Receive display, file transfer, and native assets

- The UI owns retained display history separately from raw receive-to-file capture. Session uses a separate pending UI-delivery ring capped at 512 KiB and 512 events; overflow discards the oldest pending records while RX/TX counters still include every byte. Display limits count raw event payload bytes, including outgoing history, rather than HEX expansion or timestamps. Eviction drops whole oldest events with a 16,384-byte headroom target and always retains the newest event, even if oversized.
- Retained display history packs small events into blocks with variable-length payload sizes, direction bits, and lossless timestamp deltas. Large events retain their existing immutable payload. Replay and eviction preserve the original event boundaries, with no independent event-count limit.
- On overflow, the receive log updates the editor with a prefix edit and a tail append rather than resetting the whole text. It replays the evicted events to calculate the removed display length, then repairs the retained prefix until the UTF-8/GB18030 pending bytes and packet/newline state converge. Text outside the changed ranges keeps its selection and scroll anchors. Changing display options still reformats retained history.
- HEX layout counts RX and TX byte offsets independently, even when outgoing data is hidden. History advances its head offsets on eviction so replay can align rows without reflowing the retained tail. Packet headers keep their own line boundaries. The receive editor disables soft wrapping only in HEX mode.
- The data-display dropdowns for encoding, buffer limit, and HEX line width fit their widest option. Selected values are centered with 8 DIPs of padding on both sides and a separate arrow area. The timestamp packet-gap input centers its value.
- Raw `.dat` capture uses a separate 512 KiB payload queue and a 128 KiB write buffer. The writer flushes when full or every second; queue overflow stops capture with an error instead of blocking serial reads or silently discarding bytes. Stop, disconnect, and shutdown flush and close the file.
- The App event pump polls for pending display or error events every 10 ms and dispatches a frontend-thread drain. At most one drain callback per session may be pending; each display drain returns at most 512 records.
- Disconnect retains capture-file reservations through actual flush/close, waits for receive and send producers to finish, and delivers terminal display records/counters on the frontend without reprocessing stale errors. Background close/stop failures live in an independently locked terminal-result registry until the frontend reports them; Shutdown collects unacknowledged results after draining jobs. Linux enumeration uses directory metadata and character-device checks only, never a UART probe-open.
- Each serial session owns an independent curve worker with a nonblocking 128-entry RX queue, retaining at most 512 KiB of the immutable 4096-byte read chunks shared with display delivery. RX enqueues capture and display before offering curve input and never takes the parser/snapshot mutex. Queue saturation drops only curve input; the next accepted batch reports lost chunks/bytes and breaks all traces, discarding any incomplete post-gap record through LF. EOF reports terminal losses even without a recovery batch. Session close flushes capture and waits for the curve worker to drain before connection invalidation. Epochs reject queued work from earlier starts, clears, or schemas; generation tags reject obsolete sessions. The worker reconstructs LF/CRLF records up to 4096 bytes and compiles rules only on apply/start. Each enabled channel grows its point buffer on demand. A positive `PointLimit` bounds the ring; explicit `0` appends without eviction. Decoding defaults an absent limit to 10,000. Limit-only edits resize buffers under the parser mutex, retaining the newest points without changing the epoch or partial record. Invalid samples, oversized records, and backwards device time also break traces. Pausing freezes the UI snapshot only; stopping acquisition invalidates pending input and preserves processed history. Closing the plot stops acquisition, invalidates queued input, and releases the parser and the view model, including its snapshot, preview, and geometry caches. Reopening initializes a fresh stopped view from saved settings. Settings snapshots deep-copy profiles/channels, preserving invalid retained rules until use.
- `CurveSnapshot.Revision` tracks sample/metadata changes; `StatsRevision` tracks counters, including dropped input. Statistics-only polls at up to 60 Hz update counters without copying points. The frontend reuses bounds, clipped path geometry, isolated dots, and stationary-pointer lookup results across statistics-only frames, keyed by data identity, preview/live mode, and viewport. MyGo also caches the chart subtree on the GPU when available; counter text still needs a window frame. Device-time ticks choose precision from the visible span instead of four significant digits.
- Dense, continuous plot segments in the same logical pixel column render as a min/max stroke. Sparse segments, clipping at the viewport edge, and breaks remain separate. This only reduces the drawing path: the parser, snapshot, exact visible Y range, and hover values still use the retained samples.
- Each curve snapshot indexes nondecreasing time runs. The ring records backwards jumps and evicts or rebases the index when retained points change. The frontend uses run endpoints for the full X range and binary searches for visible samples, keeping neighboring points for exact clipping. Hover reads the original samples. Rings cache hierarchical extrema for 256-point blocks and larger power-of-two groups. Writes invalidate the affected blocks and ancestors; publication rebuilds dirty nodes. Summaries never join across a break, time reversal, or the ring head. The plot selects the largest fully visible summary contained in one pixel column, falling back to smaller blocks or individual points for exact clipping and discontinuities.
- The frontend's live snapshot cache owns its point buffers independently from the parser. It appends newly received points and advances a contiguous sliding window; occasional compaction moves retained points when the reserved tail fills. Parser resets, limit changes, replaced snapshots, or a possible full ring revolution trigger a full copy. The original caller-modifiable snapshot API still copies all points on data changes. The opt-in Linux PTY software-rendering workload is `SERIALGO_CURVE_PERF=1 go test ./ui -run '^TestCurvePerformance$' -count=1 -timeout=2m -v`; its frame rate is not a native-window display rate.
- To measure snapshot compaction over a long run, set `SERIALGO_CURVE_PERF=1 SERIALGO_CURVE_PERF_DURATION=180s` and run only the live subtest with `go test ./ui -run '^TestCurvePerformance/live$' -count=1 -timeout=5m -v`. It reports snapshot p50/p95/p99/max and dropped input chunks/bytes; the default measurement window remains eight seconds.
- Windows has a separate opt-in synthetic native-window probe: cross-compile `CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go test -c -o curve-perf.exe ./ui`, then run it in an interactive desktop session with `SERIALGO_NATIVE_PERF=1` and `MYGO_FRAME_STATS=all`. It renders four prebuilt million-point series for eight seconds without a serial port; frame logs measure MyGo rendering/presentation, not serial throughput or compositor-confirmed display rate.
- The plot defaults to 1040 × 600 DIPs with a minimum of 720 × 260 DIPs. The minimum width keeps profile and acquisition controls on one row. Its sidebar renders compact channel summaries and acquisition enable switches; there is no separate chart legend or per-series visibility mask. Every series in the parser snapshot participates in rendering and autoscaling. Native modal child windows edit detached drafts for common profile fields and individual channels, preventing profile switches from invalidating an editor's target. The common-fields dialog defaults to and permits a minimum of 280 × 320 DIPs, with a scrollable form, a separate validation area, and centered fixed action buttons. An invalid sample limit shows a live error and disables confirmation. Confirmation calls the App command, which validates atomically and queues an independently copied background settings snapshot; cancellation and invalid input never replace active/saved settings. Active schema changes replace the parser under its mutex without changing the acquisition switch; metadata-only profile renames preserve points, partial framing, and any displayed preview. A separate modeless child window tests configured rules on demand and shares retained preview text and snapshot. Child windows close with the plot and follow UI language changes. Settings-save errors are also visible in the plot window.
- The profile sample-limit field filters non-ASCII digits and limits input to one digit more than the maximum value. Paste is applied only if the filtered insertion fits after replacing the selection; an oversized paste leaves the field unchanged. Empty or out-of-range values show an error and disable confirmation.
- Channel colors are metadata, not part of the acquisition schema. Rules cache parsed `0xRRGGBBAA` values for snapshots; color-only changes update them under the engine mutex and advance its revision without recompiling regexes or resetting points, partial records, or acquisition state. The frontend caches sidebar colors outside rendering and recolors retained previews in place. Missing legacy colors are assigned by configured channel index when decoding; invalid nonempty colors remain intact and are rejected on use.
- `CurveSnapshot.LatestX` records the latest successful sample globally, including zero or backwards device time; fixed-span live bounds use it while historical positions retain the full range. Profile selection explicitly rebuilds previews when active identity changes. Color-only edits recolor paused snapshots without replacing their points or counters. `App.DeleteCurveProfile` validates the candidate before atomically resetting acquisition history and partial framing, independently of schema equality. Channel counts have no fixed cap: rings stage record values in reusable fields until the shared timestamp is validated, sidebar colors follow the loaded draft length, and plot paths grow on demand and reuse their buffers.
- A frontend-owned focusable splitter separates a positive preferred sidebar width from session visibility and the live drag viewport. `CurveSidebarWidth` stores the preference in DIPs, defaulting to 260 for missing or invalid numeric values. Completed drags and effective arrow-key adjustments only mark changed widths dirty. A visible sidebar uses its 170-DIP content width as the minimum for dragging, keyboard resizing, and rendering saved preferences, while leaving at least 160 DIPs for the chart. Below 220 DIPs, the chart uses a short empty-state message and hides the standalone time-range caption. Time ticks retain the rightmost label and skip any labels that would collide. Rendering clamps and divider focus do not rewrite preferences. Explicit hiding releases the sidebar space without changing the saved width. Closing the plot, settings use, and normal exit save through the existing revisioned writer; visibility and active drag state are session-only. `CurveSnapshot.DeviceTime` comes from the compiled parser rather than mutable drafts: host UNIX-second timestamps display as local clock time, and explicitly configured device timestamps display as numeric seconds. Curve actions use SVG pencil/trash icons parsed once, with localized labels and tooltips; profile actions remain text buttons.
- Windows controls use Microsoft YaHei UI. The receive log uses its configured family, point size, and color; send and preset data use the system monospace font with fallback for Chinese characters.
- The lower workspace defaults to 90 logical pixels: three 24-pixel rows, two 4-pixel gaps, vertical padding, and borders. The connection card follows the content width of its Baud row: port selection on the first row, then a baud selector sized to fit `1000000` and Settings on the second. The Port selector and Settings share a right edge; the last row places the square Tools button to the left of Open/Close. File actions use two equal columns: Save data aligns with Open file, Record data aligns with Send file, and the recording button switches to Stop recording while capture is active. Raw captures retain incoming bytes in `.dat` files; capture state is runtime-only and resets on restart. File delay and Repeat interval fields are both 48 logical pixels wide. File delay uses centered digits and shares the last row with Stop, which has a localized file-send tooltip. The single send-header row puts HEX, CRLF, Repeat, a centered five-digit-width 48-logical-pixel interval field with equal horizontal padding, and right-aligned `+`/`-` Presets. The editor spans the two rows below, with Send and Clear send stacked on the right. The 800-logical-pixel minimum window width keeps this row unwrapped. The divider can still expand the workspace.
- Expanded presets share the upper workspace with the receive log. The preset pane stays at least 440 logical pixels wide; its default share is 55%, with the divider adjustable above that minimum. Each preset puts metadata and format options, including an Interval label before the interval field, on the first row; data and the Send button occupy the second.
- Both baud selectors fit the greater of the selected value or `1000000`, plus the arrow, its separate 4-logical-pixel right inset, 4-logical-pixel padding on both sides of the value, and borders. The arrow stays near the right side of the trigger; the selected value is centered inside the padded text area. The serial framing selectors match the baud selector width and center their values; the device-name picker uses the same value padding and a separate 4-logical-pixel arrow inset, and centers its selected port. File sending reads fixed 256-byte chunks; the configured delay applies between chunks, with no wait after the final chunk.
- The Port settings dialog sizes to the wider of its Baud selector row and its two action buttons, then uses the modal's symmetric horizontal padding. The selector row uses a 90-logical-pixel label and the actual Baud selector width; the action row uses two 76-logical-pixel buttons and their 8-logical-pixel gap. The RTS and DTR checkboxes are centered together.
- The single send-header row uses the shared 4-logical-pixel gap between its controls. Text and HEX editors share the same empty-input prompt. The footer orders S, R, serial settings, and status, separated by vertical bars; serial settings use the compact format `1000000 bps · 8N1`. The operation-status cell exposes its full localized message on hover.
- The receive-options panel width follows its second row: a 72-logical-pixel first column, the shared 4-pixel gap, the measured Auto scroll checkbox, and symmetric panel padding/borders. Its right edge aligns with Auto scroll plus the normal 7-logical-pixel inset; Clear and Options divide the reduced row width equally.
- Maintain only `assets/icon.svg`. The SVG's serial-port outlines and curve control points are mirrored about its vertical centerline, with a solid light circular background. `cmd/appicon/` generates PNG, multi-size ICO, and Windows `.syso` resources; do not manually edit or commit generated icons.
- Windows loads the embedded ICO for the current DPI; Linux supplies the embedded PNG to GTK. Native title-bar icon display remains the window manager/compositor's decision. Keep native window decorations rather than adding a custom title bar to force an icon.

## Build and verification workflow

Use Go 1.27.4 or later, Just, and Bash. Build recipes live directly in `justfile`, without standalone build scripts or a C cross-compiler. Both `just windows` and `just linux` embed the default configuration and generate icon resources first; `just build` invokes the Windows build. These explicit build commands do not launch the application.

| Command | Output |
| --- | --- |
| `just build` / `just windows` | `build/windows-amd64/SerialGo.exe` |
| `just linux` | `build/linux-amd64/SerialGo` |

Prepare generated resources with `just _icon` before running focused Go tests directly from a clean working tree. Choose tests for the changed area: encoding and business behavior in `internal/`, receive-display and layout behavior in `ui/`. The `just linux` recipe builds only; it does not run tests.

`just test` is a Windows build/deploy/launch recipe, not a Go unit-test runner. It depends directly on `windows`. If `/mnt/d/project/SerialGo` exists, replace only its `SerialGo.exe`; otherwise skip deployment without creating the directory. Preserve the destination configuration.

If copying fails, convert the destination with `wslpath`, invoke `/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe` to terminate the process at that exact executable path, and retry copying once. Do not rebuild or change configuration during the retry. After a successful copy, enter the deployment directory and launch with `setsid`; do not launch after a failed copy.

For Windows desktop verification, connect directly to `cth-win10`, build with `just windows`, and replace only `Desktop/SerialGo/SerialGo.exe`. Preserve its existing configuration, launch in the logged-in desktop session, and use run-specific scheduled tasks if needed. Clean up only the verification processes, tasks, scripts, and temporary files created for that run; retain the application and configuration. Without a physical or virtual COM port, report only the UI, settings, and error paths actually exercised, not successful serial I/O.
