# SerialGo

[English](README.md) | 简体中文

Go 原生串口调试助手. 接收窗口占据主区域, 底部为紧凑的文件工具条、串口参数、发送区和状态栏. 多条发送面板可在右侧展开. 设置直接显示在界面中, 不再保留重复的菜单栏. 界面使用 MyGo, 不依赖 WebView、Node.js 或 TypeScript 绑定.

## 构建与运行

需要 Go 1.27.4 或更新版本、Just 和 Bash. 编译命令直接写在 `justfile` 中, 不需要独立编译脚本或 C 交叉编译器. 默认构建不启动程序.
原生 UI 依赖在 `go.mod` 中固定为 [MyGo v0.9.0](https://github.com/egoist/mygo/releases/tag/v0.9.0).

| 命令 | 产物或行为 |
| --- | --- |
| `just` / `just build` / `just windows` | `build/windows-amd64/SerialGo.exe` |
| `just linux` | `build/linux-amd64/SerialGo` |
| `just test` | 构建 Windows 版; 仅当 `/mnt/d/project/SerialGo` 已存在且复制成功时, 更新其中的 `SerialGo.exe` 并后台启动 |

两个平台的构建都会先嵌入仓库根目录 `config.toml` 默认模板并生成图标资源. 从干净工作区直接运行聚焦 Go 测试前, 先执行 `just _icon` 准备这些资源. `just test` 虽然名为 test, 实际是 Windows 构建、部署和启动命令, 不是 Go 单元测试命令. Linux 命令只构建, 不运行测试.

`just test` 复制失败时, 会结束目标可执行文件路径对应的 Windows 进程并重试复制一次, 不重新编译. 最终复制成功后进入发布目录, 用 `setsid` 后台启动 EXE. 不创建不存在的目标目录, 不修改配置, 复制失败时不启动. 重试需要 WSL 的 `wslpath`, PowerShell 使用绝对路径 `/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe` 调用, 不依赖 Windows PATH.

Linux 运行需要图形会话、GTK 3 和对应串口的读写权限. 创建和保存配置需要可执行文件所在目录可写.

## 语言

点击左下串口设置下方的 "选项", 再使用弹窗内的语言按钮切换中英文, 工具条不再单独显示语言按钮. 英文界面显示 **简体中文**, 中文界面显示 **English**, 表示点击后切换到的语言. 控件, 对话框, 状态文本和提示会立即切换, 无需重启, 并立即将语言选择保存到 `config.toml`. 已经显示的状态消息和当前打开的选项弹窗也会切换语言. 默认使用英文 (`en`), 简体中文保存为 `zh-CN`. 已有配置缺少语言选项或语言值无效时, 使用英文.

语言选择只改变应用界面文字, 不翻译串口收发数据、用户输入、文件内容、预设名称或指令、协议值. 五条默认预设在两种语言下均保持名为 `Preset 1` 至 `Preset 5`. 操作系统和第三方库的原始错误详情也保持原样.

## 使用

- 文件工具条提供文件操作及多条发送面板开关. 左侧第一行由连接指示灯和端口选择框组成, 与第二行左右边缘对齐. 指示灯在串口关闭时为红色, 打开时为绿色, 悬停提示和无障碍名称说明当前连接状态, 不随收发数据闪烁. 第二行依次为 "波特率" 标签、波特率下拉框、串口设置和打开/关闭. 波特率框固定为可完整显示 `1000000` 的紧凑宽度, 不随剩余空间拉伸; 面板宽度按内容自适应, 不再固定. 下方同一行放 "保存数据", "接收存文件", "选项", 下一行放独立生效的 "HEX 显示" 和 "HEX 发送" 同组开关. "选项" 按 "窗口与语言" 和 "数据显示" 分组. 置顶和语言切换分别占一行; 数据显示第一行为编码选择, 后面依次为显示发送记录复选框, 时间戳分包复选框及同一行的分包超时. 置顶仅当前运行有效. "显示发送记录" 将本机发出的数据也显示在接收窗口中, 用 `TX >` 和 `RX <` 区分方向, 不会再次发送数据. 右侧仅保留定时发送及其间隔/单位, 回车换行, 发送, 清空发送和发送输入框. "回车换行" 后依次为 "发送" 和 "清空发送", 均位于输入框上方. "清计数" 仍在底部收发计数旁. 数字延时框可完整显示五位数. 文件延时仍紧邻 "发送文件" 按钮之后; 悬停文件路径可查看完整内容.
- 选项弹窗直接从 "窗口与语言" 分组开始, 顶部不再重复显示 "选项" 标题.
- 底部工作区按左侧四行控件收紧并平衡两侧高度, 不再在串口设置下方留下大片空白. 拖动文件工具条上方的横向分隔线可调整接收和发送区域的高度, 最小尺寸约束保证小窗口中输入框及控件仍可用. 双击分隔线恢复紧凑的默认分配. 分隔位置仅当前运行有效, 不修改配置.
- 程序启动时自动枚举串口, 每次通过鼠标或键盘展开端口下拉框时再枚举一次, 不再提供独立 "刷新" 按钮. 空列表仍可展开刷新, 已展开时不会随界面重绘反复枚举; 已连接时锁定端口选择. Windows 在端口号后显示设备名称, 例如 `COM12 USB-SERIAL CH340`; 无设备描述时只显示端口号. Linux 保留设备路径显示. 打开串口和保存配置始终使用原始设备名, 不包含显示描述. 刷新保留仍可用的当前端口, 否则选第一项; 无设备时清空选择并禁用 "打开", 但下拉框仍可用. 端口选择框保持宽度, 长内容省略显示; 未连接和连接后锁定时, 鼠标悬停均显示当前选择的完整内容. 默认选中波特率 115200. 设置数据位、校验位和停止位后打开串口. RTS 和 DTR 可在连接时切换.
- 点击 "串口设置" 打开模态属性框, 配置波特率、数据位、停止位、校验位、RTS 和 DTR. 这些参数全局共用, 不按设备分别存储; 切换端口不会重置它们, 属性框不显示当前端口号或设备名称. "确定" 应用并保存有变化的参数; "取消"、Esc 或关闭属性框丢弃草稿. 参数未变时确定也不写盘. 已连接时帧格式只读, 仅可修改 RTS/DTR; 驱动失败在框内提示, 不提交设置. 主面板保留波特率快捷选择, 不再显示 RTS/DTR 或展开式帧格式控件.
- 两处波特率选择框使用 `config.toml` 中完整的 `BaudRates` 数组, 初始为 `9600`、`19200`、`57600`、`115200`、`921600`、`1000000`, 不区分初始项和新增项. "自定义..." 添加并选中新值, 列表去重并按数值排序. 右键任意数值项, 选择 "删除" 后确认即可移除; 取消或 Esc 不改变列表和当前选择. 主面板确认新增或删除后立即保存; 串口属性框内的变更仅修改草稿, 外层确定才保存, 外层取消或 Esc 会撤销. 删除当前值后选择剩余第一项; 删空后保持空数组, 禁用 "打开", 直到重新添加数值. 重启不会补回已删项. 也可退出程序后直接编辑数组. 旧配置缺少 `BaudRates` 时迁移旧波特率值; 显式新数组 (包括 `[]`) 始终优先于旧键. 输入接受 1 到 4294967295 的整数, 实际支持范围由设备和驱动决定.
- 底部串口状态和收发计数保持单行显示, 鼠标悬停在对应单元格可查看完整文本提示.
- 发送区支持文本 (UTF-8 / GB18030), HEX 和定时发送. 勾选 "回车换行" 会在发送内容末尾追加 `\r\n`. HEX 接受连续字节, 空格或逗号分隔的字节, 例如 `01030000` 或 `01 03 00 00`. 不再自动计算或追加校验码; 协议需要校验字节时, 请自行写入发送内容. 串口属性里的奇偶校验不受影响. 旧发送校验配置不再生效, 后续正常保存时省略旧键, 不会仅因加载而重写已有文件.
- 接收窗口可切换文本或 HEX, 并显示发送记录. "时间戳和分包显示" 为单个开关: 勾选后按设定的空闲超时时间分包, 每包显示时间戳; 取消勾选后同时关闭两者. 分包超时与开关显示在同一行, 未勾选时禁用. 沿用已有 `Timestamp` 和 `PacketGap` 值; 原独立 `Packet` 键不再生效, 后续正常保存时省略, 不会仅因加载而重写文件. 新数据可显示后始终回到最新一行, 包括此前选中了前文或连续收到自动换行的长内容时. 无新数据时不干预手动翻阅历史. 收发计数按实际字节数统计. "保存数据" 导出当前窗口文本; "接收存文件" 保存串口收到的原始字节. "发送文件" 按每 256 字节分段, 可设分段延时.
- 点击工具条 "扩展" 展开预设面板. 面板不另显示标题, 只显示配置中的实际条目, 最多 99 条, 不再补齐空槽位. "新增" 追加空条目并滚动到该条; 每条提供 "删除", 确认后删除, 取消不改变列表. 删除后保留其余条目的顺序和内容, 按当前顺序连续编号. 新增和确认删除立即保存, 新增的空条目也会保留. 可以删空, 重启后仍为空; 已有条目包括空条目均不会被自动裁剪. 发送任务运行期间禁用增删. 面板较窄时, 备注及同组的 HEX/CRLF/间隔/删除控件自动换行. 新生成的配置仍默认提供 `Preset 1` 至 `Preset 5` 五条名称不同的条目. 单条发送, 按顺序发送勾选项, 循环和停止行为不变.

## 配置与数据安全

配置仅支持实际运行的可执行文件 (bin) 同目录下的 `config.toml`, 并解析可执行文件的符号链接. 不读取启动工作目录、用户配置目录或其他位置的配置, 保存失败时也不回退到其他目录.

启动时若文件不存在, 立即生成默认配置. 已有配置不会因加载而被覆盖; 无法读取或解析的配置也不会被替换. 无法创建或保存时报告错误; 可执行文件所在目录须可写.

仓库根目录的 [`config.toml`](config.toml) 是默认设置的唯一来源, 也便于用户对照. Just 编译前将它复制为生成的内嵌资源; Go 从该模板解析默认值, 不再维护第二份默认值. 可执行文件仍可独立运行, 运行时不读取仓库模板. 已有的 EXE 同目录配置保留原值, 缺失的标量字段使用内嵌默认值. 预设列表缺失或显式为空时表示没有条目, 不会补回新配置的五条默认预设.

已提交的编辑标记参数已修改, 不逐字写盘, 也不启动保存定时器. 属性框草稿在确定前与实际设置分离. 实际使用时才保存有修改的参数: 成功打开串口, 接受发送任务, 成功导出显示数据或开始接收存文件, 确认有变化的串口属性, 新增或确认删除预设, 以及立即生效的显示选项, 语言或面板变更. 参数未修改时不重复写盘, 定时和循环发送也不逐包保存. 正常退出先等待后台保存完成, 再保存尚未使用的修改; 无修改则不写盘. 后台保存使用独立快照, 包括独立的预设和波特率列表, 旧保存结果不会清除后续修改的标记. 保存失败保留修改标记, 下次使用时重试, 后续的操作成功消息不会掩盖保存错误. 强制结束进程可能丢失尚未保存的修改.

## 外观

Windows 界面控件使用系统字体微软雅黑 UI. 接收日志, 主发送输入框和预设数据使用系统等宽字体, 中文字符使用系统字体回退. 图标保留黑色串口图案和浅色实心圆底, SVG 轮廓与曲线控制点关于垂直中心线严格左右镜像. 图标已内嵌到程序, 无需在可执行文件旁额外放置图标文件. Windows 窗口按当前 DPI 加载内嵌 ICO, 避免将大尺寸 PNG 再次缩小导致细线发虚; Linux 窗口使用内嵌 PNG. 图标源文件只维护 `assets/icon.svg`, PNG、多尺寸 ICO 和 Windows `.syso` 资源均在构建时生成.

## 限制

- 提供的构建命令面向 Windows amd64 和 Linux amd64. Linux 需要满足上述图形环境及串口权限要求.
- Linux 将内嵌 PNG 交给 GTK 作为窗口图标. 是否在原生标题栏或桌面其他位置显示, 由窗口管理器/合成器决定; GTK 不保证标题栏显示图标. 仅凭标题栏无图标不能认定图片加载失败. 参见 [GTK 窗口图标约定](https://docs.gtk.org/gtk3/method.Window.set_icon.html). 程序保留原生窗口装饰, 不为强制显示图标而替换成自绘标题栏.
- 配置的波特率是否受支持由串口驱动决定; 多条发送面板最多 99 条. 配置只保存在可执行文件目录, 不回退到用户目录.
- 接收跟随会在每次追加可显示数据时滚到底部; 向上翻看历史不会暂停跟随.
- 真实串口收发需要可用的物理或虚拟串口. 仅构建程序或启动界面不能证明串口收发已通过验证.

## 串口库迁移评估与延后计划

**结论: 值得隔离试用, 但必须等其他应用功能回归测试完成后再进行. 当前没有替换依赖或串口后端.** 目前仍使用 `github.com/albenik/go-serial/v2 v2.6.1`, 应用尚未提供自动流控选项.

### 候选与维护情况

- 当前库最新标签仍为 [`v2.6.1`, 对应源码提交日期为 2024-01-28](https://proxy.golang.org/github.com/albenik/go-serial/v2/@latest), [默认分支最后提交](https://github.com/albenik/go-serial/commit/594ef15cc4760409acc4074b486375a6de28bf54)也在同一天. 仓库未归档, 但维护停滞确实是风险, 不能据此认为近期仍在活跃维护.
- 原始上游 [`go.bug.st/serial v1.8.0`](https://github.com/bugst/go-serial/releases/tag/v1.8.0) 发布于 2026-07-15, 维护比当前库更新, 但稳定版接口仍不含流控; [RTS/CTS PR #201](https://github.com/bugst/go-serial/pull/201) 尚未合并.
- 试用候选为 [`github.com/briardhq/go-serial v1.8.0-briard.1`](https://github.com/briardhq/go-serial/tree/v1.8.0-briard.1), 对应提交 `7fa2b2eddb3a0968a2eea9467c39e33e098f526b`, 提交日期为 2026-09-30. 流控实现在 `briard` 分支, 不在 `master`. 它基于上游 v1.8.0, 加入 RTS/CTS 补丁及 Windows RTS 握手修正. 其 [README](https://github.com/briardhq/go-serial/blob/v1.8.0-briard.1/README.md) 明确说明只是等待上游发布该功能前的临时 fork, 不能当作长期维护承诺. 如果正式迁移前上游已提供等效稳定支持, 优先选择上游.

### 已确认的实现与迁移阻碍

- 候选库声明 Go 1.25.0, 模块依赖只有 `golang.org/x/sys`. 当前构建工具链 Go 1.27.4 已满足该工具链下限, 但这不能替代下述 I/O 行为验证.
- 源码中 `Mode.RTSCTSFlowControl` 会设置 Linux `CRTSCTS`, 并在 Windows 同时启用 CTS 发送门控及驱动自动管理 RTS 握手. 它**不提供** XON/XOFF 软件流控或 DTR/DSR 流控. 这些结论来自源码检查, 不是硬件验证.
- `SetMode` 没有应用流控字段的变更. 除非另行修正并验证, 否则切换流控应通过关闭并重新打开串口完成.
- 当前打开串口后会手动调用 `SetRTS`. 候选库的 Windows `SetRTS` 会替换 RTS 握手位, 因而迁移时必须在硬件流控接管 RTS 后避开该调用, 包括仅修改 DTR 的场景. 手动 DTR 及未启用流控时的手动 RTS 功能仍须保留.
- 候选库使用 `Port` 接口及 `Mode` 配置, 不是当前的具体端口类型和 option 函数. 它有 `SetReadTimeout`, 但没有公开的写超时接口. 必须保留应用的 10ms 接收空闲轮询和 250ms 写入期限, 不能悄悄把有界写入改成无限等待.
- 其 Unix 实现打开后仍把描述符切为阻塞模式. 现有非阻塞 I/O 和借用描述符的兼容处理既不能直接删除, 也不能原样照搬. Windows 现有端口枚举及设备描述应保留, 不能因换库引入主动 USB 探测.

### 历史接收兼容性门槛

用户提供的 UART 换库历史是新增的迁移阻碍, 不是现在换回去已经安全的证据. 提交 `8873737` (2024-08-29) 将实际 UART 入口切到 albenik, 并明确记录首字节超时策略会 "break rx data", 而 `SetReadTimeout` 配合 `ReadyToRead` 更好、更快. 后来的互斥锁修改与最初换库原因是两件事. 当时的 `go.bug.st/serial v1.6.2` 实际通过 replace 使用 [`github.com/fcying/go-serial` 的 `312149864b96`](https://github.com/fcying/go-serial/tree/312149864b9635cb5702daf7966eeca833c8755a), 对照时不能假定它就是未修改的上游版本.

对照旧 fork 和 `v1.8.0-briard.1` 的源码, **不能认定历史接收问题已修复**:

- 两者在 Windows 的正数读超时下仍使用首字节返回配置, 即 `ReadIntervalTimeout` 和 `ReadTotalTimeoutMultiplier` 均为 `MAXDWORD`. 新版 CH340 处理把无限或极大超时常量改为 `0x7FFFFFFE`, 不能据此证明当年正数 1ms 超时路径的问题已修复.
- 旧 fork 在读超时且无数据时返回 `Timeout` 错误, 候选库在配置了读超时时返回 `(0, nil)`. 适配层必须保持调用者预期, 不能把这项语义变化当成已修复丢数据的证据.
- UART 当前包装层采用 `ReadyToRead` 轮询、立即读取和外部期限控制. SerialGo 当前 Windows 后端则使用 10ms 首字节超时, `Session.receive` 持续复制每次返回的全部字节. 两者消费方式不同, 一次 `Read` 完成不等于一个协议帧; 显示分包和原始字节是否完整也要分开判断.
- Albenik 也提供 `SetFirstByteReadTimeout`, 但 UART 实现刻意避开了它. 迁移应保留这套轮询规避方式, 或证明等效接收行为可靠, 不能仅凭库版本更新就接受迁移.
- 已审查的 briard `Port` 接口没有公开的 `ReadyToRead` 方法, 因而不能直接照搬 UART 的规避方案, 也不能假定其 `SetReadTimeout(0)` 等同于 albenik 的立即读取模式. 等效等待和读取路径需要单独评估. 当前 SerialGo 策略与 UART 不同, 但仅凭历史记录也不能认定 SerialGo 存在丢数据故障.
- UART 当前 `ReadLength` 还会先读入较大缓冲区, 再把复制长度截到目标剩余长度, 没有保留超出的已读字节. 多帧同时到达时, 必须将这类上层截断与库缺陷分开排查. 本次评估不修改 UART 代码.

正式考虑换库前, 优先在同型号适配器和驱动上复现当年的接收负载. 以相同数据、波特率、超时和接收负载, 对比已经可用的 UART 轮询策略与固定版本候选: 单字节到达、包头后延迟到达包体、连续多帧、突发数据、持续流量、超时后再来数据. 用原始字节顺序、序号或校验及总字节数检查丢失、重复和截断, 不能只对比单次 `Read` 长度或显示换行. 测试调用方的定长读取超额消费问题也应先排除, 避免污染比较结论. 缺少这些证据时, 历史问题仍属未验证; 即使 RTS/CTS 生效也不能据此接受迁移.

### 延后试用与采用条件

1. 先完善基础应用功能并完成回归测试, 再重新核查上游和 fork 的维护情况、可用版本、流控修复、接收接口及历史超时问题, 然后决定是否试用迁移. 本节只是当前评估记录, 不是届时自动换库的批准. 如果复查后仍值得试用, 再作为独立后端变更实施, 固定届时重新审查的标签和提交, 不跟随浮动分支.
2. 保持 `communication/serialport` 包装层契约、EXE 同目录配置、已保存的帧格式和控制线值、预设及 UI 行为不变. 在后端内适配打开、超时、错误和句柄所有权; 不能只换 import 就算完成迁移.
3. 采用前验证 Windows 实际串口收发、自定义波特率、文件发送、分包间隔显示、手动 RTS/DTR、CTS 阻塞与恢复、驱动管理 RTS、写超时、停止和关闭响应、断线重连及反复开关串口. 使用真正支持握手信号的硬件或虚拟环境, 仅启动 UI 不算通过.
4. Linux 继续按现有约定默认只构建. 未实际验证时, 不宣称 Linux I/O 或硬件流控通过. 只有现有超时、取消保证及 Windows 串口行为得到实际证明后, 才接受此次试用迁移.
