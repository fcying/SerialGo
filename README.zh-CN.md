# SerialGo

[English](README.md) | 简体中文

面向 Windows 和 Linux 的原生串口调试助手, 支持文本和 HEX 收发, 接收日志, 文件传输及可编辑发送预设.

## 快速开始

1. Windows 运行 `SerialGo.exe`, Linux 在图形会话中运行 `SerialGo`. EXE 所在目录须可写, 以便创建和保存同目录的 `config.toml`.
2. 选择串口和波特率, 再点击 "打开". 初始波特率为 `115200`; 需要调整帧格式或控制线时点击波特率旁的 "设置".
3. 在发送区输入文本或 HEX 字节并点击 "发送". 需要时在 "选项" 中选择文本编码.
4. 上方窗口显示接收数据. 点击 "保存数据" 将当前显示日志导出为 `.txt`, 点击 "录制数据" 可在连接后开始保存原始接收字节.

底部从左到右为连接控制, 接收控制, 文件操作和发送输入区. 主窗口的位置, 正常尺寸和最大化状态保存在可执行文件同目录 `config.toml` 的 `[Window]` 表中. 保存矩形至少需与某个显示器的工作区重叠 100x50 逻辑像素, 否则保留尺寸并居中. Windows 保存原生像素边界以避免不同 DPI 显示器间位置漂移; 旧配置缺少像素边界且显示器缩放比例不同时会居中. 新配置默认居中, 尺寸为 800x600. 分隔线位置不保存.
窗口最小宽度为 800 逻辑像素, 以便发送控件保持在同一行.

## 连接与波特率

- 启动时枚举串口, 每次通过鼠标或键盘展开端口下拉框时刷新. 关闭后重新展开即可重试, 不另设刷新按钮. 枚举失败保留原列表和选择.
- Linux 枚举只读取设备节点元数据, 不打开串口, 不修改波特率, 帧格式或流控. 列出的节点仍可能不可用, 只有明确打开时才报告相应错误.
- Linux 板载 UART 支持带数字后缀的 `ttyTHS`, `ttyPS`, `ttySAC`, `ttySTM`, `ttymxc`, `ttyLP` 等命名, 同时保留原有 USB, ACM, 标准 UART 和 RFCOMM 类型. 控制台和伪终端名称不作为串口列出.
- Windows 尽可能显示设备描述, 如 `COM12 USB-SERIAL CH340`; Linux 显示设备路径. 悬停可查看省略名称的完整内容, 连接锁定后仍可查看. 打开和保存使用实际设备名, 不含描述.
- 刷新保留仍可用的当前端口, 否则选第一项. 空列表清除选择并禁用打开按钮. 连接后锁定端口和波特率选择框.
- "设置" 用于调整数据位, 校验位, 停止位, RTS 和 DTR. 设置全局共用, 不按设备分别保存; 底部状态栏显示当前帧格式. 已连接时仅可修改 RTS/DTR; 驱动错误会在对话框中提示, 不应用未确认的变更.
- Linux 不接受 5 数据位与 2 停止位的组合: 该字长下 termios 的长停止位设置可能产生 1.5 个停止位. 需要时请选择 1.5 停止位.
- "确定" 应用属性框变更; 取消, Escape 或关闭弹窗丢弃草稿. 参数未变时确认不写盘. 帧格式只在设置框编辑, 不在主面板重复显示.
- 打开/关闭按钮左侧的 **⋯** 按钮打开工具菜单. 选择 "串口曲线" 可从接收日志提取数值并在独立窗口绘图, 详见[串口曲线](#串口曲线).

波特率选择框初始提供 `9600`, `19200`, `57600`, `115200`, `921600` 和 `1000000`:

- "自定义..." 添加并选中波特率, 去重后按大小排序. 输入接受 `1` 到 `4294967295` 的整数, 实际支持范围由设备和驱动决定.
- 右键数值项选择删除并确认, 取消或 Escape 不修改. 删除当前值后选择剩余第一项.
- 主面板增删立即保存. 设置框内的增删在外层确定前均为草稿, 外层取消或 Escape 会丢弃.
- 列表删空后重启仍为空, 禁用打开按钮, 直到新增波特率. 也可退出程序后编辑 `config.toml` 的 `BaudRates`.

## 串口曲线

打开 **⋯ > 串口曲线**, 点击 "配置" 打开独立配置框, 编辑方案名称、可选时间正则、时间倍率和 "每条曲线采样上限". 每个方案可设每条曲线保留 1 到 1,000,000 点. 填 `0` 则不限, 内存占用随采样增长. 新建方案和未保存上限的旧方案默认 10,000 点. "确定" 校验后应用修改, 并自动保存到可执行文件同目录的 `config.toml`; 取消, Escape 或关闭配置框丢弃未确认的修改. "开始" 重新开始采集. 最多支持 16 个方案, 每个方案不设曲线数量硬上限. 内存占用及解析和绘制开销随通道数增长.

采样上限输入框只保留 ASCII 数字, 最多输入 8 位. 粘贴后若超过 8 位, 整次粘贴会被拒绝, 输入框保持不变. 空值或超出范围的数字会显示错误并禁用 "确定", 直到修正.

- 左侧仅放置可独立滚动的曲线列表, 首次使用 260 逻辑像素宽度, 手动调整后通过 `config.toml` 的 `CurveSidebarWidth` 记住宽度. 可拖动分隔条或用方向键调宽度, 最窄为 170 逻辑像素, 保持控件可见. 完全收起请用 "隐藏". 缩小窗口时只限制侧栏的实际显示宽度, 为波形区至少保留 160 逻辑像素, 不覆盖记住的宽度; 放大窗口后恢复可用宽度. 窄版隐藏 "显示范围" 字样, 保留下拉框和历史滑块. 打开配置框不改变列表宽度. 每条曲线显示启用开关, 名称, 提取规则, 单位和色条. 前缀规则直接显示匹配内容, 不加 `前缀:` 字样. "+ 添加" 和每条曲线的铅笔图标打开独立编辑窗口, 垃圾桶图标用于确认删除; 图标保留本地化悬停提示和可访问名称. "确定" 校验后立即应用并保存; 取消, Escape 或关闭窗口丢弃未确认的编辑. 启用/禁用曲线和确认删除也会自动生效. 无效输入在对应对话框内提示错误, 不替换最后有效的活动规则或已保存配置. 通道或时间规则变化会清空旧曲线历史及半行数据, 但保持正在采集或已停止的状态; 仅重命名方案保留历史. 未变更的编辑不写盘. 保存失败会提示错误并保留脏状态, 正常退出时再次刷新.
- "隐藏 / 显示" 按钮只切换侧栏显隐, 不清除记住的宽度. 再次显示时恢复该宽度, 仅受当前窗口可用空间限制. 调整侧栏宽度不立即写盘. 关闭曲线窗口时, 新宽度与其他待保存设置一并写入配置. 重启后按保存的宽度显示侧栏, 显隐状态本身仅在当前会话保留. 旧配置缺少宽度, 或数值非正及非有限时, 使用 260.
- 曲线列表直接显示配置的曲线名称, 不额外添加 `CH1`, `CH2` 等编号前缀. 已保存的名称和曲线顺序保持不变.
- 每条曲线的编辑框提供颜色选择器和 HEX 输入. 颜色保存在 `config.toml` 的 `CurveProfiles[].Channels[]` 中的 `Color` 字段, 支持 `#RRGGBB` 和带透明度的 `#RRGGBBAA`. 侧栏色条, 图表, 悬停值及提取结果使用同一颜色. 禁用或删除其他曲线不改变它的颜色; 单独修改颜色保留已有采样及预览. 旧配置未指定颜色时按配置中的通道顺序补默认色, 加载时不改写文件.
- "前缀" 提取指定字面前缀后的有符号十进制或科学计数法数字, 允许中间有空格. 例如日志 `[ADC] VBAT=3712 mV`, 设置前缀 `VBAT=`, 倍率 `0.001`, 偏移 `0`, 单位 `V`, 得到 `3.712 V`.
- "正则 (Go/RE2)" 使用 Go 标准库 [`regexp`](https://pkg.go.dev/regexp), 采用 RE2 风格语法, 不是 PCRE/PCRE2. 不支持前后查找, `\1` 这类反向引用或 RE2 的 `\C`. 实现版本随 Go 工具链发布, 没有独立的 RE2 库版本号; 编辑窗口显示当前构建的 Go 版本. 第一个捕获组作为数值, 例如 `battery:\s*([-+]?\d+(?:\.\d+)?)`. 每条启用的曲线每行最多提取一个值, 同一行可匹配多条曲线. 换算公式为 `数值 × 倍率 + 偏移`. 可选时间正则也使用相同语法.
- 横轴默认使用电脑接收时的系统时间和系统时区, 显示时分秒, 短时间范围和悬停值显示到毫秒. 跨多次读取的日志行使用完成该行时的接收时间, 同一批接收的多行可能具有相同时间戳. 在 "配置" 中填写可选时间正则后, 使用第一个捕获组乘以时间倍率作为设备时间, 横轴改为设备秒数而不是日历时间. 鼠标悬停时间正则输入框时, 在其下方显示 "留空 / 填写" 两种情况的简短提示; 鼠标移出即隐藏, 不因输入框保留键盘焦点而继续显示. 时间正则为空时, 时间倍率输入置灰但保留数值, 重新填写正则后恢复编辑. 设备运行时间按数值时间轴绘制, 不作为 UNIX 时间戳转换为日期, 也不叠加电脑时间. 例如日志 `uptime_ms=12345 VBAT=3712`, 配置 `uptime_ms=(\d+)` 和倍率 `0.001`, 得到 `12.345 s`. 清空时间正则恢复系统时间, 不丢弃倍率. 切换时间模式会清空原模式的历史和半行数据; 时间回退或串口重连后分段绘制.
- 设备时间复位或回退后, 固定时间范围的实时视图跟随最新收到的采样, 不再停留在旧的最大时间戳. 历史滑块和 "全部" 仍可查看保留的历史.
- 设备时间刻度精度随可见范围调整, 长时间运行后相邻刻度仍可区分, 例如 100,000 秒附近的 60 秒窗口. 普通范围显示十进制秒数; 极大数值或极小范围可能采用科学计数法.
- Y 轴刻度精度也随可见范围调整, 使较大基值附近的微小变化仍可区分.
- 当浮点精度大于所选实时窗口时, 图表使用最接近的可表示区间, 并将最新设备时间采样保持在右侧. Y 轴标签空间随显示数值调整.
- 悬停标签保留采样值和设备时间的存储精度, 即使相邻采样位于同一对刻度之间, 也能区分不同的数值和时间.
- 右上角 "测试规则" 按需打开日志测试窗口, 粘贴日志后点击 "预览提取", 测试当前配置输入, 不保存它们, 不改变实时采集. 测试窗口显示结果, 曲线窗口同步绘图; 无效输入提示错误. 系统时间模式下为每行模拟一秒间隔, 最后一行对应当前电脑时间; 设备时间模式下使用粘贴日志中的时间. 最后一行可以没有换行符.
- 切换方案时, 已显示的预览按新方案的规则和时间模式重新提取.
- 默认测试日志交替放置三条电压记录 (`VBAT=3712 mV`, `VBAT=3680 mV`, `VBAT=3740 mV`) 和三条电流记录 (`IBAT=1024 ua`, `IBAT=926 ua`, `IBAT=1524 ua`). 两条曲线分别使用前缀 `VBAT=` 和 `IBAT=` 提取. 倍率都设为 `0.001` 时, 单位分别使用 `V` 和 `mA`. 默认示例不修改已有方案的提取规则.
- "暂停查看" 冻结显示快照, 后台继续采集. 单独改色只更新颜色, 不替换冻结的采样或计数. 选择时间范围并移动历史滑块查看保留的数据, "实时跟随" 返回最新快照. 悬停图表可查看附近采样值. 启用的曲线共用自动缩放的 Y 轴, 建议使用兼容单位.
- 曲线窗口默认大小为 1040 × 600 逻辑像素, 最小可缩到 720 × 260. 缩到最小宽度时, 工具栏控件仍保持单行显示. 关闭时将大小和位置独立于主窗口保存到 `config.toml`, 再次打开或重启应用后仍会恢复. 图表上方不再显示通道图例, 增加通道不会挤占图表高度. 通过左侧曲线列表的启用开关管理通道; 改变启用通道会重置曲线历史.
- "停止" 保留当前历史, 再次 "开始" 会重新采集. "清空" 仅重置曲线数据和计数, 不改变采集开关. 关闭曲线窗口会停止采集并丢弃采样、计数、预览和未确认的编辑. 重开时加载已保存的规则, 图表为空且不自动采集.
- 暂停查看时停止采集会保留冻结画面; 点击 "查看最终快照" 可显示停止时保留的数据.
- 如果其他保留规则仍无效, 导致已编辑的曲线规则尚未应用, 关闭曲线窗口或主窗口前会确认是否丢弃草稿.
- 删除活动方案时清空该方案的采样, 计数和未完成的日志行, 即使下一方案的规则相同. 下一方案有效时保持原来的采集状态; 删除最后一个方案或选中保留的非法方案时停止采集, 并显示相应规则错误. 已保存的通道仍可查看和编辑, 打开时不截断或保存原配置.
- 稀疏曲线按时间窗口边缘裁剪, 不会因为原始采样都在窗口外而消失. Y 轴缩放包含可见线段的交点; 悬停仍查询真实采样, 不把插值伪装成接收数据.
- 曲线处理不会等待式阻塞串口读取或原始录制. 处理跟不上时, 曲线窗口显示丢失的输入块数和字节数; 缺失输入前后断段, 不跨缺口连线. 无关日志只更新统计, 不替换已绘制的采样.
- 串口读取跨越曲线开始、清空或规则变更时, 该批数据不进入新曲线; 不完整记录丢弃到下一个换行. 接收显示和原始录制仍保留这些字节.

曲线只处理 LF 或 CRLF 结尾的接收日志, 不受接收区 HEX/文本显示、显示历史淘汰或原始录制影响, 可跨串口读取边界拼接行. 不匹配的行不生成采样; 无效数字会计数并跳过. 超过 4096 字节的行丢弃到下一个 LF. 调小上限只丢当前采集历史里最旧的点, 调大则保留还在的点. 两者都不会重启采集或替换暂停查看时冻结的采集快照. 历史和采集开关不持久化. 本工具不解码二进制帧或仅以 CR 分行的日志.

## 发送数据

- 文本支持 UTF-8 和 GB18030. 发送区的 HEX 开关接受连续字节或空格, 逗号分隔, 如 `01030000` 或 `01 03 00 00`.
- 在 **选项 > 发送** 中启用 "解析转义符" (默认关闭). 开启后, 文本模式解析 `\\`, `\a`, `\b`, `\f`, `\n`, `\r`, `\t`, `\v`, `\0` 和 `\xNN`; `\xNN` 直接发送指定原始字节, 不再经过文本编码. 未知、格式错误或不完整的转义会阻止整次发送. HEX 模式不受影响.
- "CRLF" 位于发送区 HEX 右侧, 在发送末尾追加 `\r\n`, 与串口帧格式无关.
- "选项 > 发送" 中的校验算法支持 `None` (默认), `XOR8`, `SUM8`, `SUM16-LE`, `SUM16-BE`, `Modbus CRC16` 和 `CRC16-CCITT-FALSE`. 帧头和帧尾排除数按字节计, 均默认为 `0`. 校验仅计算排除边界之间的数据, 并插入被排除的帧尾字节之前. `CRLF` 最后作为帧终止符追加, 不计入排除长度. 主发送与预设发送共用设置. `SUM16` 按 16 位回绕, `LE`/`BE` 分别表示低/高字节在前.
- 勾选 "定时" 并设置毫秒间隔, 即可按该间隔重复发送当前内容.
- "发送" 开始发送当前内容; "清空发送" 清除输入. 文本和 HEX 模式在输入为空时均提示 "输入发送内容...". "停止" 可取消文件发送; 悬停可查看 "停止文件发送" 提示.

## 接收显示与文件

- "HEX 显示" 切换文本或 HEX. 在接收控制区勾选 "显示发送" 可查看本机发送的 `TX >` 记录及接收的 `RX <` 记录, 不会再次发送数据.
- 在 "选项 > 数据显示" 中设置 "HEX 每行字节数", 可选 16、32、64, 默认 32. HEX 显示按固定宽度分行, 不使用软换行; 分包处和裁剪后的首行可能不足一行. 文本显示和原始录制不受影响. 复制或导出 HEX 显示日志时保留换行.
- "时间戳" 按空闲间隔分包并添加时间戳. 在选项中设置 "时间戳分包超时", 默认 `20 ms`. 无效编辑保留为草稿并显示错误, 修正后才生效.
- 串口会话结束时结束其文本解码流, 不会将不完整字符与下一次连接的数据拼接; 重建显示历史时也保留会话边界.
- "自动滚动" 跟随最新数据. 关闭后仍接收, 但保留当前视口; 重新开启后回到最新行. 新数据保留已有选区, 自动滚动关闭时也一样. 选中文字时暂时暂停跟随, 不会关闭自动滚动. 在接收窗口内单击, 松开鼠标后清除选区并恢复跟随. 仅向上滚动不会关闭跟随. 如果选区 caret 已被滚出视口, 文本控件仍可能在更新后将其滚入可见区域. 自动滚动状态不保存.
- 接收窗口的复制仅复制选中文字. 无选区时不改动剪贴板.
- "清空" 清除接收日志, 并将底部 S/R 收发字节计数同时归零. 串口参数采用如 `1000000 bps · 8N1` 的简写格式; 悬停可查看串口参数和操作状态的完整文字.
- "打开文件" 选择普通文件, 悬停 "发送文件" 可查看完整路径. "延时" 设置文件发送分块之间的毫秒等待, 最后一块后不额外等待. 接收日志下方的临时文字显示文件名、百分比和成功写入字节数, 约每 200 ms 更新一次, 不写入 RX/TX 历史. 发送成功后文字消失; 取消或失败时保留最后进度和原因, 直到选择或发送其他文件. 使用 "停止" 取消发送, 发送中显示的百分比始终低于 100%.
- 过长的进度消息保持单行, 悬停可查看完整文字. 尚未获取文件大小就取消时, 百分比显示为 `--%`.
- 分块间隔较长且没有串口接收数据时, 仍会刷新已成功写入的字节数. 手动断开显示取消; 串口读取异常断开显示对应原因.
- 文件进度使用发送开始时已打开文件的大小. 发送期间修改文件可能导致百分比与实际发送字节数不一致.
- 文件大小使用十进制单位, 不显示科学计数法. 发送刚结束时关闭串口仍保留该任务的实际结果.
- 保存显示数据和原始录制只接受普通输出文件. Linux 上打开输出 FIFO 不会阻塞应用. 文本或预设发送在断开期间发生写入失败时仍会报告.
- "保存数据" 将显示日志导出为 `.txt`. "录制数据" 将原始接收字节保存为 `.dat`. 如果录制跟不上串口接收, 会停止录制并报告错误, 不阻塞接收或静默丢弃数据. 停止录制, 断开串口或退出时刷新并关闭文件. 录制需要已连接串口, 重启后不会自动续录, 已完成的 `.dat` 文件保留在磁盘.
- 断开连接后完成剩余收发记录和计数的交付. 录制目标在最终刷新并关闭前始终禁止被导出覆盖, 包括硬链接别名. 停止录制或断开后立即退出, 仍会报告刷新和关闭失败.

### 显示历史上限

在 "选项 > 数据显示 > 显示缓冲上限" 中选择 `200K`, `500K`, `1M`, `2M`, `5M` 或 `10M`, 默认 `2M`. 单位采用十进制 (`K = 1000`, `M = 1000000`), 按原始事件数据字节数计算, 包含发送记录, 不计 HEX 展开和时间戳.

超限后整条删除最旧事件, 最新事件即使单条超限也保留. 调小上限立即裁剪历史, 调大不会恢复已淘汰数据. 不提供无限制选项或单独记录条数上限. 需要不受显示上限影响的原始数据时, 使用 "录制数据".
小块接收采用紧凑存储, 不缩减所选的原始字节容量, 也不改变时间戳分包边界.

## 发送预设

点击 "扩展" 在接收日志旁展开预设列表, 拖动分隔线调整空间. 点击 "收起" 折叠面板.

- 新配置初始包含 `Preset 1` 至 `Preset 5`. 只显示实际配置条目, 最多 99 条, 不补齐空槽位.
- 每条可编辑备注, 内容, HEX/CRLF 开关和间隔. 支持单条发送, 按顺序发送勾选项, 或勾选循环后重复发送. 停止可结束当前任务.
- "新增" 追加空条目并滚动到该条. 删除须确认, 取消不修改. 剩余条目保留顺序并连续编号.
- 新增和确认删除立即保存, 空白条目也保留. 可以删空全部条目, 重启仍为空. 发送期间不能增删.

## 语言与外观

在接收控制区打开 "选项". 英文界面的语言按钮显示 **简体中文**, 中文显示 **English**, 表示目标语言. 控件, 对话框, 提示及已有状态立即切换, 无须重启, 并保存选择. 默认英文 (`en`), 简体中文使用 `zh-CN`; 缺失或无效语言值使用英文.

切换语言不翻译或重置串口数据, 用户输入, 文件, 预设备注和指令, 协议值, 或操作系统及第三方库原始错误. 两种语言的默认预设名均为 `Preset 1` 至 `Preset 5`.

选项还提供置顶, 文本编码, 默认关闭的文本转义解析, 校验算法和帧头/帧尾排除字节数, 显示历史, 时间戳分包超时及接收字体设置. 接收字体默认宋体, 9 磅, 黑色, 使用标准 16 色调色板. 发送内容和预设使用系统等宽字体, 中文使用字体回退. 图标已内嵌, 不须另放图标文件.

## 配置与数据安全

- 仅使用实际可执行文件同目录下的 `config.toml`, 并解析 EXE 符号链接. 不搜索工作目录或用户配置目录, 保存失败不回退到其他目录.
- 当 `config.toml` 的链接链和已有目标都位于可执行文件目录时支持符号链接. 悬空或指向目录外的链接会被拒绝, 不覆盖链接或回退到其他位置.
- Windows 下配置目标不能是 `.config.toml.lock` 或其硬链接; 请使用同目录的其他目标文件, 避免保存锁与配置冲突.
- 导出和接收存文件在截断前检查配置文件及其已有的符号链接和硬链接别名. 不要在操作期间通过其他进程更改这些链接或路径.
- 配置缺失时立即创建. 已有文件, 包括无法读取或解析的文件, 加载时不覆盖. 创建和保存失败会提示, 请保证 EXE 目录可写.
- 仓库的 [`config.toml`](config.toml) 是默认参考, 不是运行时依赖. EXE 同目录已有值保留, 缺失标量字段使用默认值. 预设列表缺失或显式为空时保持为空, 不恢复初始条目.
- 设置在实际使用时保存, 包括成功连接, 接受发送任务, 文件导出或接收存文件, 确认属性, 预设增删, 以及立即应用的显示, 语言或预设面板变更. 编辑不逐字写盘. 正常退出保存剩余草稿和窗口几何; 强制结束可能丢失近期修改. 未修改的使用和退出不重写文件.
- 保存错误保持可见, 下次使用重试. 已存编码或分包超时无效时使用 UTF-8 和 `20 ms` 并显示启动警告, 加载不重写文件. 显示上限无效时使用默认值.
- 保存前若检测到配置目标或内容在加载或上次保存后被外部更改, 会报告冲突并保留未保存标记. 请保留需要的编辑, 使用预期配置重新启动以解决冲突. 协作实例通过 EXE 同目录的 `.config.toml.lock` 串行保存; 锁文件会保留. 不协作的写入者仍可能与检查发生竞态.
- 保留的非法曲线规则不阻止其他偏好设置保存. 多个旧方案同时非法, 或旧列表超过 16 个方案的新增上限时, 仍可逐个修正或删除. 新增或编辑的方案必须有效; 开始采集时独立校验所选方案, 不受原样保留的其他非法方案阻挡.
- 旧配置缺少 `BaudRates` 时迁移旧波特率值, 显式数组 (包括 `[]`) 优先. 旧发送校验和独立 `Packet` 设置被忽略, 下次正常保存时省略, 不因加载而重写. `Timestamp` 和 `PacketGap` 继续支持.

## 运行环境

- Windows amd64, 或带图形会话和 GTK 3 的 Linux amd64.
- 所选串口的读写权限.
- 可写的 EXE 所在目录, 用于创建和保存配置.

源码构建, 测试和部署见 [构建与验证流程](ARCHITECTURE.zh-CN.md#构建与验证流程).

## 限制

- 提供的构建面向 Windows amd64 和 Linux amd64. 波特率及控制线支持由驱动决定. 当前没有自动流控设置.
- Linux 窗口图标显示由窗口管理器或合成器决定, 仅标题栏无图标不能证明加载失败. 参见 [GTK 窗口图标约定](https://docs.gtk.org/gtk3/method.Window.set_icon.html).
- 实际收发需要物理或虚拟串口, 构建或 UI 启动成功不代表串口 I/O 已通过验证.
